# 스테이지 배경 규격과 작업 방법

슬라임 왕국 전투 배경(2026-11-24, 커밋 `66088ef`)을 만들며 확정한 규격과 순서. 다른 테마도 이 문서대로 만든다.

배경은 **한 장짜리 그림이 아니다.** 바닥까지 그린 **베이스 1장** 위에 **PixelLab 오브젝트를 하나씩 얹고**, **Light2D 환경광**을 깐다.

---

## 1. 무대 기준 (코드 값)

| 항목 | 값 | 위치 |
|---|---|---|
| 시점 | 사이드뷰. 플레이어 왼쪽, 몬스터 오른쪽 | `AreaView` |
| 카메라 | 직교, `orthographicSize` 3.2 (화면 높이 6.4유닛), 기준 16:9 | `Dungeon.unity` |
| 픽셀 밀도 | **PPU 64**, Point 필터, 압축 없음 (`Art/` 아래 PNG 는 자동) | `PixelArtImportSettings` |
| 발 높이 | 화면 아래에서 **37%** | `AreaView.GroundViewY = 0.37` |
| 캐릭터 / 몬스터 배율 | **0.75** (64px 그림 = 0.75유닛) | `AreaView.ActorScale = 0.75` |
| 플레이어 자리 (x) | 0.10 / 0.20 / 0.30 / 0.40 | `AreaView.PlayerSlots` |
| 몬스터 자리 (x) | 0.631 / 0.762 / 0.892 | `AreaView.MonsterSlots` |
| 캐릭터 정렬 | 레이어 `Default`, order 10 | `AreaView.MakeActor` |
| HUD | 1080p 기준 아래 약 180px 까지 (유물 줄 176px). 발(약 400px)과 안 겹침 | `CombatHud.uss` |

> 발 높이나 배율을 바꾸면 모든 테마의 배경 위치가 같이 움직인다. 바꾼 뒤 각 테마의 `BaseGroundLine` 을 다시 맞출 것.

## 2. 파일 구성

```
Assets/Terminus/Art/Backgrounds/<테마키>/        그림 (PNG, 자동 임포트)
  base.png                                        베이스 (불투명)
  <오브젝트>.png                                  오브젝트 (투명, 여백 잘라낸 것)
Assets/Terminus/Resources/Visuals/Backdrops/<테마키>.asset   배경 에셋 (StageBackdrop)
```

테마키: `slime`, `lava`, `lizard`, `forest`, `spirit`

| 코드 | 하는 일 |
|---|---|
| `Runtime/Art/StageBackdrop.cs` | 테마 하나의 배경 데이터 (베이스, 오브젝트, 빛). `LoadByTheme(테마 이름)` |
| `Runtime/Game/Client/StageBackgroundView.cs` | 지금 층 테마(`ClientState.Map.ThemeName`)의 배경을 카메라에 맞춰 깔고 빛 / 블룸 생성. 던전 씬에서 `UIApp` 이 만듦 |
| `Editor/BackdropPreview.cs` | 미리보기 PNG (메뉴 아래 5절), `Background` 정렬 레이어 추가 |

배경 에셋의 `ThemeName` 은 몬스터 DT 의 `Theme_KR` / `DungeonServer.TierThemeNames` 와 **같은 글자**여야 한다 (예: `슬라임 왕국`). 에셋이 없는 테마는 배경 없이 검은 화면 + 캐릭터만 나온다.

## 3. 레이어와 정렬

정렬 레이어 **`Background`** (Default 보다 먼저 = 뒤) 를 쓴다. 배경 그림은 전부 여기, 캐릭터는 `Default`.

| 순서 (order) | 무엇 | 예 (슬라임) |
|---|---|---|
| -100 | 베이스 | `base.png` |
| -61 ~ -60 | 뒤쪽 바닥 가장자리 오브젝트 (캐릭터 뒤) | 등불 기둥, 슬라임 결정, 석상 |
| -20 | 앞쪽 판석 위 소품 (캐릭터보다 아래쪽에 놓되 정렬은 뒤) | 버섯 웅덩이 |
| Default 10 | 캐릭터 / 몬스터 | |

배치 원칙
- 캐릭터가 서는 줄(x 0.08~0.42, 0.60~0.92 / y 0.37 근처)은 큰 오브젝트로 가리지 않는다.
- 큰 오브젝트는 **화면 양 끝** 또는 **두 진영 사이(x 0.45~0.55)**.
- 빛나는 오브젝트(등불, 결정)를 하나 이상 두어 점광원 자리로 쓴다.

## 4. 에셋 규격

### 4.1 베이스

| 항목 | 규격 |
|---|---|
| 크기 | **688×384** (16:9, PPU 64 에서 화면을 확대 없이 거의 꽉 채움) |
| 내용 | 하늘 → 원경 → 중경(언덕) → **바닥 판석** → 아래 벽돌. 캐릭터 / 오브젝트 / 글자 없음 |
| 바닥 | 판석 윗면이 **한 줄로 이어진 가장자리**. 그 아래 판석 띠(약 25px)에 발이 섬 |
| 바닥선 | 발이 닿을 픽셀 줄(위에서)을 `BaseGroundLine` 에 적음. 지금 기준(발 37%)으로 그림 높이의 약 **63%** (슬라임: 243) |
| 색 | 몬스터보다 채도·대비 낮게 |

`StageBackgroundView` 는 베이스를 화면을 덮는 최소 배율로 늘린 뒤, `BaseGroundLine` 이 발 높이에 오게 올리고 내린다. 그만큼 위아래가 비면 **더 확대**하므로, 바닥선은 처음부터 그림에서 맞는 자리에 있어야 확대가 안 생긴다. 1~2줄 어긋나면 그림을 위아래로 몇 px 밀어서(빈 하늘을 잘라내고 맨 아래 어두운 줄을 덧붙임) 맞춘다.

### 4.2 오브젝트

| 항목 | 규격 |
|---|---|
| 생성 캔버스 | 96×96 ~ 128×176 (4의 배수) |
| 실제 그림 | 캔버스의 절반 정도만 채워 나옴 → **투명 여백을 잘라낸 PNG** 로 저장 (예: 96×176 → 48×92) |
| 크기 감 | 기둥·석상 약 50~60×90px, 소품 약 100×40px. 캐릭터(64px × 0.75)보다 조금 큰 정도 |
| 피벗 | 가운데 (임포트 기본). 코드가 발밑을 `ViewPos` 에 맞춤 |
| 외곽선 / 음영 | 첫 오브젝트를 스타일 참조로 계속 넣어 통일 |

## 5. 작업 순서 (PixelLab + Unity)

### 5.1 베이스

1. **처음 생성**: `create_image_pro`, 688×384, `no_background=false` (25회).
   - 설명에 "flat walkable stone floor, top edge one straight horizontal line at N% from the top" 를 넣어도 **높이는 잘 안 지킨다.**
2. 바닥선이 안 맞으면 **밑그림을 만들어 다시 그린다.**
   - 기존 베이스를 잘라 붙여, 바닥 윗선이 원하는 줄에 오는 688×384 밑그림을 만든다 (언덕 쪽을 세로로 줄이고 바닥 띠를 늘림).
   - 그 밑그림을 `reference_images` 에 "exact composition and layout" 으로 넣고 `create_image_pro` 로 다시 그린다 (25회). 구도는 거의 그대로 따른다.
3. 바닥 가장자리가 **점선 / 두 줄** 로 남으면 그 띠만 인페인트한다.
   - `inpaint_image` 는 가로 512px 까지라 **344×96 조각 3개를 겹쳐서** 차례로: 0~344 / 172~516 / 344~688. 두 번째부터는 앞 조각 결과를 왼쪽 문맥으로 남기고 오른쪽만 마스크 (마스크 x 160~344, 높이 18~20px).
   - 조각당 10회. **띠는 얇게**: 큰 영역을 조각으로 나눠 다시 그리면 조각마다 톤이 달라 사각 경계가 보인다.
   - 결과에 **하얀 빈칸**이 생기면 그 둘레만 작은 조각(200×96)으로 한 번 더 인페인트.
4. 바닥선을 재서 `BaseGroundLine` 을 적고 미리보기로 확인. 발이 판석 **가장자리가 아니라 가운데**에 오게 몇 px 아래로 잡는다.

### 5.2 오브젝트 (하나씩)

1. **스타일 참조 만들기**: 첫 오브젝트는 베이스에서 96×96 을 잘라 `style_image` 로 쓴다 (참조는 캔버스 안에 들어가야 함).
2. `create_object_pro_flash`, `view="side"`, `n_directions=1` (96px 이하 5회, 100~208px 6회).
   - 설명: 무엇 + "Dark outline, muted colors except the glow. Fills most of the canvas, bottom flat on the ground. Transparent background."
3. 받은 PNG 의 **투명 여백을 잘라낸다** (안 자르면 바닥에서 떠 보임).
4. 배경 에셋 `Props` 에 추가 (`Sprite`, `ViewPos` = 발밑 화면 비율, `Order`). 미리보기 → 사용자 확인.
5. 첫 오브젝트가 통과하면 **그 오브젝트를 `style_image` 로** 나머지를 같이 생성 (참조보다 캔버스가 커야 함).

### 5.3 환경광

배경 에셋의 빛 값만 채우면 `StageBackgroundView` 가 만든다.

| 값 | 뜻 | 슬라임 왕국 |
|---|---|---|
| `AmbientColor` / `AmbientIntensity` | `Background` 레이어 전역광 (분위기) | (0.55, 0.62, 0.85) / **0.6** |
| `ActorLightColor` / `ActorLightIntensity` | `Default` 레이어 전역광 (캐릭터 가독성) | 흰색 / **1.0** |
| `Glows[]` | 점광원 (`ViewPos`, 색, 세기, 반경 유닛). 두 레이어 모두 비춤 | 아래 표 |
| `BloomIntensity` | 블룸 (threshold 0.75, scatter 0.55 고정). 0 이면 끔 | **0.35** |

| 점광원 | ViewPos | 색 | 세기 | 반경 |
|---|---|---|---|---|
| 등불 | (0.057, 0.56) | (0.55, 1, 0.45) | 0.95 | 1.9 |
| 결정 | (0.50, 0.52) | (0.45, 1, 0.75) | 0.9 | 2.7 |
| 버섯 웅덩이 | (0.47, 0.37) | (0.6, 1, 0.4) | 0.6 | 1.1 |

원칙: 배경은 어둡게(0.5~0.8), 캐릭터 빛은 1.0. 점광원은 은은하게(세기 1 이하). 블룸은 0.3~0.6.

### 5.4 확인

1. **미리보기**: 메뉴 `Terminus/Art/Render Backdrop Previews` → `Temp/BackdropPreview/<테마키>.png` (1280×720, 직교 3.2, 플레이어 3 + 몬스터 3 을 실제 자리에). 코드에서는 `BackdropPreview.Render(backdrop, 경로, 몬스터 이름...)`.
2. **실제 화면**: `Dungeon.unity` 를 열고 플레이 → 지도에서 전투 방 → 게임 뷰를 **16:9** 로 두고 확인 (Free Aspect 면 에디터 창 크기라 더 확대돼 보임).

## 7. 함정 (이번에 겪은 것)

| 증상 | 원인 | 해결 |
|---|---|---|
| 캐릭터가 언덕 위에 떠 있음 | 베이스 바닥이 발 높이보다 낮게 그려짐 | 밑그림으로 다시 그리기 (5.1), `BaseGroundLine` |
| 넓은 땅 띠를 생성했더니 캔버스 가운데에 작게만 그려짐 | 가로로 아주 긴 캔버스(728×176)는 잘 못 채움 | 땅을 따로 만들지 말고 베이스에 바닥까지 그림 |
| 벽돌 줄을 반복해 이어 붙이니 이음매가 보임 | 수작업 반복 | 같은 이유로 쓰지 않음 |
| 조각별 인페인트 후 사각 경계 | 큰 영역을 조각마다 다시 그리면 톤이 다름 | 가장자리 띠처럼 **얇은** 영역만 조각으로 |
| 오브젝트가 바닥에서 뜸 | 생성 PNG 의 투명 여백 | 여백 잘라내기 |
| 바닥선을 맞췄더니 배경이 확대되고 꼭대기가 잘림 | 이동한 만큼 빈 곳을 채우려고 확대 | 그림 자체를 몇 px 밀어 바닥선을 맞춤 |
| 미리보기에 점광원이 안 나옴 | Light2D 의 컬링 구 / 메시는 `LateUpdate` 에서 계산, 미리보기는 그 전에 렌더 | 미리보기에서 `UpdateMesh` / `UpdateBoundingSphere` 를 먼저 호출 (게임에선 문제 없음) |
| 정렬 레이어 추가 시 `type is not a supported int value` | `uniqueID` 가 부호 없는 정수 | `uintValue` 로 씀. ID 0 이면 Default 와 겹쳐 빛이 꺼짐 |
| 배경 어두운 빛이 캐릭터까지 덮음 | `Background` 레이어가 없을 때 | 레이어가 없으면 코드가 빛을 끄고 경고 (`Terminus/Setup/Add Background Sorting Layer`) |
| 게임 뷰가 1920×991 | Free Aspect = 에디터 탭 크기 | 게임 뷰를 16:9 로. 빌드는 1920×1080 전체 화면 |
| 던전 씬을 바로 플레이하면 늘 같은 테마 | 진행 중인 세이브 지도를 이어 씀 | 세이브는 지우지 말고 확인할 테마가 나올 때까지 진행 |
